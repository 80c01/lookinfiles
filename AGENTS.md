# AGENTS.md

Guidelines for AI coding agents working in this repository.

## Project overview

`file explorer` written in C with GTK+ 3 (API 3.10+). Modular architecture in `src/`,
no external dependencies beyond GTK (with optional VTE and GtkSourceView).

Two-pane layout: left = real listing of the current working directory
(`GtkTreeView` + `GtkTreeStore`, expandable directory tree with lazy-loading), right = text viewer /
directory listing, both inside a resizable `GtkPaned`.

## Build & run

```bash
make              # build (gcc -Wall -Wextra, pkg-config gtk+-3.0)
make clean        # remove binary
./explorateur_fichiers   # run (requires a display; shows a warning without one)
```

There is no test suite, and no display available in the sandbox
(`Gtk-WARNING: cannot open display` when run headless is expected, not a bug).
Validate changes by compiling cleanly; the user tests interactively.

The binary `explorateur_fichiers` is generated by make — never edit it.

## Architecture (keep it when editing)

The codebase is organized into modules under `src/`:
- **`app_types.h`**: Shared type definitions (`AppData`, `FileEntry`, `EditorTab`),
  sort enums (`SORT_*`), constants (`PREVIEW_*`, `MINIMAP_WIDTH`), and library headers.
- **`file_list.c` / `file_list.h`**: Directory enumeration, file icons, sorting
  (`populate_store()`, `compare_entries()`), directory navigation (`reload_directory()`,
  `refresh_listing()`, `activate_selected_entry()`), top bar label (`update_path_label()`),
  and tree key event handling (`on_tree_key_press()`).
- **`viewer.c` / `viewer.h`**: Right-pane viewer logic, file content loading, syntax
  highlighting and Dark+ scheme setup, text scrolling/jumping, selection changed listener,
  and filesystem monitoring (`GFileMonitor`).
- **`markdown.c` / `markdown.h`**: Rich Markdown parser and renderer (tags setup, headings,
  task lists, tables, styled quotes, code blocks, inline formatting, and images).
- **`html.c` / `html.h`**: Rich HTML parser and renderer (tags setup, title, headings,
  formatted lists, blockquotes, preformatted code, tables, inline formatting, links, and images).
- **`pdf.c` / `pdf.h`**: PDF document rendering engine using `poppler-glib` and Cairo
  (`render_pdf_preview()`), page rasterization, metadata display, and text extraction.
- **`editor.c` / `editor.h`**: Multi-tab editor inside viewer notebook (`editor_open_file()`,
  `editor_save_current()`, `editor_close_current()`, unsaved confirmation dialog).
- **`minimap.c` / `minimap.h`**: Scaled file overview with Cairo caching, slider positioning,
  and viewport navigation.
- **`terminal.c` / `terminal.h`**: Embedded VTE terminal panel management (`Ctrl+T`),
  Dark+ ANSI theme, multi-pane tracking, and child process exits.
- **`search.c` / `search.h`**: Live substring search entry (`/`, `n`, `N`) for both
  the treeview file list and the viewer buffer.
- **`ui.c` / `ui.h`**: Paned layout toggle/rebuild (`Ctrl+Shift+L`), pane resize feedback
  popup, floating help cheat sheet (`h`), fullscreen toggle (`f`), panel focus cycling
  (`Alt+Left/Right`), and screen CSS styling.
- **`main.c`**: Application entry point, CLI arguments parsing (`-f`/`--fullscreen`),
  widget creation and layout assembly, signal wiring, and `gtk_main()`.

Key widgets, in creation order in `main()`:
window → `path_label` (top bar) → store/tree_view → left/right `GtkScrolledWindow`
→ `AppData` wiring → `GtkPaned` → `outer_vbox`.

Shortcut list to keep in sync with `README.md` when you change behavior.

## Conventions and hard rules

1. **English only** — every user-visible string, code comment, commit message,
   and documentation file must be in English. No French anywhere.
2. **GTK API correctness**:
   - `GtkScrolledWindow` is a `GtkBin`: one child only. Put extra widgets in
     a `GtkBox`/vbox, or above the pane.
   - `gtk_list_store_set(store, &iter, col, value, -1)`: the terminator is the
     integer `-1`, never the string `"-1"`.
   - `GtkTextBuffer` accepts valid UTF-8 only. Validate content with
     `g_utf8_validate()` / sanitize with `g_utf8_make_valid()` before inserting
     file contents.
   - Change list contents with `gtk_list_store_clear()` + repopulation; the
     tree view holds its own reference to the model, so unref'ing `store` once
     is enough.
3. **Performance**: never load a whole huge file into the right pane; keep the
   preview path (`fread` of `PREVIEW_BYTES` only). Directory enumeration is
   O(n) with one `g_stat` per entry — fine for typical directories; do not add
   recursive scans on the UI thread.
4. **Top bar is single source of truth** for directory/sort/hidden state via
   `update_path_label()`; do not duplicate that state elsewhere.
5. `Ctrl+Q` quits via `GtkAccelGroup`; keep it working when adding key
   handlers (do not swallow the accelerator).
6. **Keep the current layout** (GtkPaned + GtkSearchEntry + outer_vbox). Do not
   switch to GtkGrid fixed cells or plain GtkBox: resizability is a user
   requirement.
7. Language: C99-ish (`-Wall -Wextra` must stay clean; the only tolerated
   warning is `-Wformat-truncation` on the initial label `snprintf`).
   Zero warnings are expected otherwise (unused variables do not compile here).

## Git

- The user expects a commit after each accepted change (one change = one commit).
- Commit messages: short imperative summary, change-focused (subject only,
  no body needed). Example: `Add Ctrl-F / Ctrl-B paging in left panel`.
- `git add` only files you deliberately changed. Amend only your own
  immediately-prior commit (e.g. forgotten fix), never user work.
